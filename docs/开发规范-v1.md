# noobbaozi · 开发规范 v1

> 适用：后续所有开发、测试、回归；**包括由子代理并行执行的开发任务**。
> 上游依据：`配装理解-软件设计-v1.md`（架构与分层）、`配装理解-字段规格-v1.md`（字段与口径）。
> 本文档的约束优先级高于实现便利。

## 0. 一句话原则

> **确定性优先。可算的必须由代码算，不可算的必须标出来，绝不让任何环节"看起来合理"。**

## 1. 环境与依赖

```powershell
# 工作区根目录
$env:UV_CACHE_DIR = "$PWD\noobbaozi\spike\uvcache"
uv run --python 3.13 --no-project --with "eveshipfit-dogma-engine[sde]==13.6.0" python -m pytest -q
```

规则：

1. **引擎版本必须 pin**（当前 `13.6.0`），不写范围版本。
2. 新增任何依赖必须：写进本文档「依赖登记」表 + 说明为什么标准库不够用。
3. 不得在代码里写死绝对路径；所有路径走配置。
4. 缓存目录固定在 `noobbaozi/spike/uvcache`（已 gitignore）。

## 2. 模块边界与写入范围

按设计文档 §5 的目录划分。**一个文件同一时刻只有一个 owner。**

| 模块 | 目录 | 允许依赖 |
|---|---|---|
| 数据层 | `noobbaozi/sde/` | 仅标准库 + sqlite3 |
| 计算层 | `noobbaozi/engine/` | `sde/`、引擎包 |
| 投影层 | `noobbaozi/project/` | `sde/`、`engine/`、`config/` |
| 接口层 | `noobbaozi/api/` | 全部下层 |
| 配置 | `noobbaozi/config/` | 无 |

硬规则：

- **禁止反向依赖**（`sde/` 不得 import `engine/`）。
- **禁止跨层直接读内部结构**：跨层只走公开函数；不得互相 import 私有 `_xxx`。
- 投影层**不得**直接调用引擎（必须经 `engine/adapter.py`），否则缓存与版本记录会漏。

## 3. 契约先行（并行开发的前提）

任何跨模块接口，**先合契约、再并行实现**。契约包括：

1. 函数签名（参数、返回类型、异常）；
2. 数据结构（TypedDict / dataclass），字段名与单位后缀；
3. 错误结构。

契约文件位置：`noobbaozi/contracts.py`（单文件，全员只读；修改需 PR 级审查）。

契约未合并前，实现方**不得自行发明字段名**——发现缺字段就停下来提契约变更。

## 4. 编码约定

### 4.1 命名与单位

- 字段名必带单位后缀：`_s` / `_m` / `_mps` / `_pct` / `_au_s`。
- 无单位语义的纯数值字段必须带 `_raw` 或在契约里注明。
- **内部一律物理单位**（秒、米）。毫秒与 ×1000 缩放只允许出现在 `project/units.py` 的解析入口，不允许出现在业务代码。

### 4.2 数值处理

- 禁止 `float == float` 比较；统一用 `math.isclose(rel_tol=1e-9)` 或比较容差常量。
- 禁止魔法数：所有阈值、缩放系数、属性 ID 集中到 `config/` 下的常量表，并注明来源。
- 属性 ID 必须用常量名引用（`ATTR_ALIGN_TIME`），不得裸写数字。

### 4.3 错误处理

- 解析类错误必须返回**可修复结构**（行号、原文、失败位置、候选、原因），不得只返回布尔或抛裸异常。
- 无法确定时**报错，不猜**。歧义（如同名多版本）一律报错并给候选。

### 4.4 provenance（强制）

- 任何输出到用户的数值，都必须能给出 `measured` / `assumed` / `unknown`。
- **禁止用默认值冒充 `unknown`**。
- 默认假设必须来自 `Assumption Engine`，不得在投影层另设默认值。

### 4.5 输出元信息（强制）

每个对外响应必须包含：

```json
"meta": { "sde_build": "...", "engine_version": "13.6.0", "spec_version": "v1" }
```

### 4.6 可选参数不得造成静默退化（强制）

> **如果一个可选参数不传会改变行为（退化），那么退化必须产生可见信号；否则禁止提供这条退化路径。**

本项目已因此踩坑**三次**（同一类错误）：

| 实例 | 后果 |
|---|---|
| acceptance 脚本调 `default_assumptions(fit, engine)` 未传 index | 跑在 19 技能旧档，快照比对**假绿** |
| `tools/derive_provenance.py::load_sample()` 同样未传 index | provenance 三态表在错误的技能基线上推导 |
| `recalculate` 前的 `derive_skill_tier` 本身 | 直接导致一整套快照与 `needs_implant` 结论错误 |

**正确做法**（三选一，推荐第 1 条）：

1. **不提供退化路径**——必填参数就是必填；
2. 退化时**抛异常**（如「技能数 < 100 直接 `RuntimeError`」）；
3. 退化时在返回值里带显式标记（如 `skill_tier_name = "min_required_only"`）+ 调用方**必须**据此报警。

**反面教材**：`derive_skill_tier(fit, engine, index=None)` 用 `name` 区分两档是对的，但调用方全都没检查这个名字——**标记存在不等于被发现**，所以第 1、2 条优先。

## 5. 测试规范

### 5.1 四层测试

| 层 | 名称 | 内容 | 要求 |
|---|---|---|---|
| T1 | 单元 | 单位换算、×1000 缩放、调和平均、provenance 标记、错误结构 | 纯函数，无网络无磁盘 |
| T2 | 契约 | 索引查询、归一化往返、假设推导 | 用固定 fixture，不连真实网络 |
| T3 | 回归 | 抗性基线、往返无损、模式、六视角快照 | 见 §6 基线 |
| T4 | 性能 | 单次计算、六视角总耗时 | 阈值见 §6.3 |

**门禁**：`pytest -q` 全绿才允许提交；T3/T4 可单独跑但不得跳过。

### 5.2 基线分两类（关键）

**这类划分是为了让回归在 SDE 每日更新时仍然可用。**

| 类型 | 定义 | SDE 更新后 |
|---|---|---|
| **不变式** | 与游戏数值无关的恒等式 | **永不允许改**，改了就是 bug |
| **快照** | 与 SDE build 绑定的具体数值 | 重新标定，并人工 diff 审查改动 |

## 6. 回归基线

### 6.1 不变式（永久有效，改一即 bug）

| # | 不变式 | 断言 |
|---|---|---|
| I1 | `EHP = shieldEhp + armorEhp + hullEhp` | 容差 1e-6 |
| I2 | `alpha = Σ 逐装备 volley` | 容差 1e-6 |
| I3 | `ehp_mixed = Σ_layer HP_layer / Σ_i(w_i × r_i,layer)`（**这是不变式**）；「与四系算术平均不同」只是**启发式观察**，不得当红线 | 复算容差 1e-6；启发式差值为 low 级观察 |
| I4 | EFT 往返无损（`save → load → calculate` 8 项指标一致） | 容差 1e-6 |
| I5 | 抗性叠加：**单模块时 = 基础共振率 × 模块共振率**；**多模块时受堆叠惩罚**，不能用简单相乘验证 | 单模块：逐层四项一致；多模块：走「逐模块移除实验」，移除量 ≠ 模块标称值属正常 |
| I6 | 输出中每个数值都带 provenance | 全字段检查 |
| I7 | 解析失败必含可修复结构 | 结构校验 |

## 7. 子代理协作规范

> 这一节是为并行开发而写，**违反它造成的返工比串行还慢**。

### 7.1 任务粒度

每个子代理任务必须自包含，且包含以下六项**缺一不可**：

```
1. 目标：一句话可验收的结果
2. 输入契约：依赖哪些已合并的函数/数据结构（含文件路径）
3. 输出契约：交付哪些文件、哪些函数签名
4. 写入范围：允许修改的精确文件/目录列表（超出即违规）
5. 验收命令：可复制执行的单条命令 + 期望输出
6. 禁区：本任务明确不允许碰的东西
```

### 7.2 依赖与并行

- 有依赖关系的任务必须声明 `blocked_by`，**不得靠"先写完再对齐"**；
- 同一文件不得分给两个并行任务；
- **契约任务永远先做**（索引 schema、数据模型、字段单位表），之后才并行实现。

### 7.3 典型并行切分（P0 示例）

| 任务 | 写入范围 | 依赖 |
|---|---|---|
| P0-1 SDE 下载与解析 | `noobbaozi/sde/ingest.py` | 无 |
| P0-2 索引 schema 与查询 API | `noobbaozi/sde/schema.sql`、`noobbaozi/sde/index.py` | 契约先行（可先于 P0-1） |
| P0-3 属性字典与单位表 | `noobbaozi/sde/attribute_dict.py`、`config/attributes.py` | 无（属性清单可先固定） |
| P0-4 模式映射表 | `noobbaozi/sde/modes.py` | P0-2 |

### 7.4 交付检查（每个子代理提交前自查）

- [ ] `pytest -q` 全绿
- [ ] `git status --short` 里的改动**全部属于本任务的写入范围**（`noobbaozi/` 已是 git 仓库）
- [ ] 新增属性 ID 全部走常量
- [ ] 新增数值全部有 provenance 路径
- [ ] 无新增依赖（或已登记）
- [ ] 无网络调用（除 `sde/ingest.py`）
- [ ] **没有执行任何 git 写操作**（红线 N15；`git status` / `git diff` 这类只读命令可以）

## 8. 禁止清单（红线）

| # | 禁止 |
|---|---|
| N1 | 在计算链路引入 LLM、网络请求或随机性 |
| N2 | 解析歧义时"挑一个最像的" |
| N3 | 输出无 provenance 的数值 |
| N4 | 用默认值冒充 `unknown` |
| N5 | 对外输出毫秒、×1000 原值 |
| N6 | 把混合 EHP 当作四系平均（或反之） |
| N7 | 为让测试通过而修改基线快照 |
| N8 | 跨层直接 import 私有函数 |
| N9 | 在投影层另设默认假设（必须来自 Assumption Engine） |
| N10 | 把知识层（RAG）结果写进任何数值字段 |
| N11 | 用 `float ==` 比较数值 |
| N12 | 裸写属性 ID 数字 |
| N13 | 台账（`PROGRESS.md`）未更新就宣告任务完成 |
| N14 | 台账与实际状态不一致时继续开发（以实际为准，先修台账） |
| N15 | 子代理执行任何 **git 写操作**（`commit` / `checkout` / `reset` / `push` / `rebase`）——提交权归 Lead，并行提交必然互相踩踏 |
| N16 | 提供「不传参数就退化」的接口而不在退化时报警（见 §4.6；本项目已因此踩坑三次） |

## 11. 项目进度台账（`PROGRESS.md`）

### 11.1 定位

- **唯一状态事实源**。判断"当前做到哪"以 `noobbaozi/PROGRESS.md` 为准，不以对话记忆、也不以代码现状为准。
- 它**不是文档仓库**：讨论细节进讨论文档、字段口径进字段规格、架构进软件设计。台账只记**状态**与**索引**，一旦开始抄内容就会失准。

### 11.2 写权

- **只有 Lead 写**。子代理不得直接修改台账。
- 子代理必须在交付回报中给出可落账信息（模板见 11.4），由 Lead 入账。
- 理由：并行任务若各自写台账，必然冲突且互相覆盖。

### 11.3 必须更新的时机（任一发生即写）

| 事件 | 更新位置 |
|---|---|
| 开始 / 完成一个任务 | §4 勾选 + §1 里程碑 |
| 派发或回收子代理 | §0 阻塞点 + §4 |
| 得出新的实测硬结论 | §3 |
| 踩坑并解决 | §6 |
| 决策变更 | §7（同时回讨论文档留出处） |
| 里程碑状态变化 | §1 + §0 |
| SDE build / 引擎版本变化 | §0 表格 |
| 会话即将中断 | §0 + §4 + §9 |

### 11.4 子代理回报模板（保证可落账）

```
任务: <编号 + 名称>
结果: 完成 / 部分完成 / 阻塞
产出: <文件列表>
验收: <执行的命令 + 关键输出摘要>
偏离: <与契约的差异，无则 none>
新增硬结论: <若有，附证据>
发现的坑: <若有，附复现方式>
未完成: <剩余项，无则 none>
```

缺 `验收` 或 `偏离` 的回报，视为**未完成**。

### 11.5 台账与其它文档的归属划分

| 内容 | 归属 |
|---|---|
| 状态、待办、里程碑、阻塞 | `PROGRESS.md` |
| 硬结论（实测） | `PROGRESS.md` §3，讨论文档留出处 |
| 决策与理由 | `PROGRESS.md` §7 + 讨论文档对应章节 |
| 踩坑记录 | `PROGRESS.md` §6；可归纳成通则的，同时写进本规范 §8 |
| 字段口径 | `配装理解-字段规格-v1.md` |
| 编码/测试/回归规则 | 本规范 |
| 快照数值变化 | `docs/回归快照-changelog.md` |

### 11.6 一致性与红线

- 对应红线 **N13 / N14**：台账未更新不得宣告完成；台账与实际不一致时**以实际为准**，先修台账再继续。
- 允许台账"落后"于实现（写延迟），但**不允许"领先"**（把没做的勾掉）。

### 11.7 中断恢复流程

按 `PROGRESS.md` §9 执行：

1. 读 §0 状态摘要与 §3 硬结论；
2. 跑自检命令（`spike/smoke3.py`，0.33 ms 量级即环境正常）；
3. 从 §4 最上面的未勾选项开始；
4. 有子代理在跑时，先核对写入范围与本规范 §7.3 的切分是否冲突。
