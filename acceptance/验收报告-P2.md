## 5. 需你裁决的口径冲突（C4）

> 这是**裁决 ↔ 实现**的冲突，不是实现 bug，也不算我的检测遗漏。

| 项 | 内容 |
|---|---|
| **原裁决** | Q5（2026-10-18）：`repair` 无对应模块的层**统一输出 `0.0`，provenance = `measured`**（"没有该模块"由输入直接决定，不是 unknown） |
| **实现主张** | `survivability._repair()` docstring 明写：「缺失给 `None`；而有效修复率引擎**给了** `0.0`（`-50`/`-49`），那就照实输出 `0.0`。**两者不是同一种「零」，不许互相冒充**」 |
| **实测** | f1（有护甲修复器）：`armor.raw_hp_s 32.5`；`shield.raw_hp_s null/unknown`、`hull.raw_hp_s null/unknown`。f2/f3（无修复模块）：三层全 `null/unknown` |
| **两种立场** | 裁决出发点：下游可直接算（null 会污染数值运算）。实现出发点：不撒谎（引擎 `-47`/`-46` 确为 `None`，标 `measured` 等于宣称"实测为 0"） |
| **下游影响** | agent 只做数值运算 → 需自己补 0；agent 读三态 → `unknown` 会把"没带护盾回充"误读成"不可知" |
| **我的建议** | 折中二选一：① 值输出 `0.0` + `provenance = assumed`（"按无模块假设的 0"）；② 保留 `null`，但在 `flags` 给一条"该层无修复模块"。两种都不撒谎且下游可算 |

裁决前我记 **low 观察**（可复现、不阻塞）。若判按原裁决执行，改完我复跑一次即可（约 1 分钟）。
