### 2.1 provenance 的判定规则（不硬编码）

`provenance` 的**权威来源是投影层** `evefit/project/provenance.py`：

- `measured` = 输入直接决定，且**不随**技能档 / 模块状态 / 模式 / 伤害剖面变化；
- `assumed` = 依赖上述四者之一；
- `unknown` = 引擎未提供（如 `-70 maxTargets` 恒 0）。

runner 的实际做法：**从投影层读权威表**（`provenance.tag(attr_id)`），与输出里声明的
provenance 逐值对拍。上表的 provenance 列只是文档；T-08 用实测重推该表后，
runner **不需要改代码**。

权威表未就绪时，runner 退化为**只做结构校验**（三态合法性 + 数值叶子全覆盖），
并在报告里明确标注「⚠️ 未就绪」，绝不用硬编码期望值冒充。

### 2.1.1 输出形态：裸值 + 平行 provenance 表（Lead 裁决 2026-10-18）

对外形态定为「**裸值 + 视角级 provenance 表**」，TypedValue 退回内部/未来接口。
理由：overview 实测 13,519 chars，若每叶裹 TypedValue 会再涨 3–4 倍，预算直接爆掉；
且 provenance 是**字段级元信息**，平行表正好对应 FIELD_SOURCES 的键空间，可整表校验。

runner 的 collect_leaves() 支持双形态（--views-json 两种都可喂）：

- **形态 A（优先，渲染层实际形态）**：
  {view: {overview: {...裸值...}, provenance: {dps.base: assumed, weapons[].name: measured}}}
- **形态 B（兼容）**：{view: {overview: {...TypedValue...}}}

键空间规则（必须与 project/render._leaf_paths 逐字一致，否则会造出假缺陷）：
对象 → prefix.key（**整数键展开成 str**，故 count_by_level.4）；非空且元素全为对象的列表 →
prefix[].key；其余（标量 / 字符串 / None / 布尔 / 空列表 / 空对象 / **标量列表**）→ prefix 本身。

**I6 判定**：形态 A 下每个叶子必须在平行表里有键——缺键且该叶子**有数值** → provenance 错误/high；
缺键且无数值（空容器/字符串）→ low 观察。形态 B 下只对**数值叶子**强求 provenance
（TypedValue 无法给字符串挂三态）。

额外自检：**平行表键集合必须等于 overview 叶子路径集合**（双向），不一致记 low——
它能提前发现遍历规则两边不同这类会掩盖缺失的问题。

### 2.2 confidence 的判定规则（稀疏表 · 输出层三档）

**权威登记表**：evefit/project/confidence.py 的 confidence_of(view, path)。
输出层只产生三档（Lead 裁决 2026-10-18）：

| 档 | 含义 |
|---|---|
| A | 口径已实测对拍（输入直接决定，或已与外部基线/不变式严格对上）——可直接当结论用 |
| C | 不可用（引擎不给值，如 -70 maxTargets 恒 0）——不要拿它做结论 |
| E | 未建模（只给参数不给结论，如 pplication.*）——agent 需自行建模 |

> B（需换算）已被投影层 units.physical() 吃掉；D（需对拍/推断）已收敛为 A
> （抗性 12/12 已对拍）。因此 ield_spec.json 里 weapons / 
eeds_implant /
> external_dependency 等在输出层都是 **A**。

**稀疏约定（T-18）**：<view>.confidence **只输出非 A** 的叶子路径；
**缺省 = A**；空表输出 {}。全量表会白白涨 +5,093 chars 撑爆预算。

runner 的四条校验：

1. 先按 overview 叶子路径补齐默认 A，再查表；
2. set(confidence) ⊆ set(provenance)（键空间必须与 overview 叶子一致）；
3. **每个非 A 登记项都必须出现**——用 confidence_of() 反查（防漏输出，漏了会被当成 A）；
4. 显式写 A 的条目违反稀疏约定 → low 观察（T-18 落地后应消失）。

## 3. 不变式 I1–I7 的检查方法

> 全部由 runner **直接从引擎独立复算**，不采信实现自报。容差 1e-6（开发规范 §6.1）。
> 快照过期不影响本节——不变式与 SDE 数值无关，永久有效。

| # | 不变式 | 检查方法 | 判定 |
|---|---|---|---|
| **I1** | `EHP = shieldEhp + armorEhp + hullEhp` | 取同一次 `calculate` 的 `-43` 与 `-30/-28/-29`，求和比对 | 差 > 1e-6 → 不变式失败(blocker) |
| **I2** | `alpha = Σ 逐装备 volley` | 取 ship `-11` 与逐 item `-21` 求和比对 | 差 > 1e-6 → blocker |
| **I3** | `ehp_mixed = Σ_layer HP_layer / Σ_i(w_i×r_i,layer)`，且 **≠ 算术平均、≠ 调和平均** | 用 `263/265/9` 与三层四系共振 ID 复算（w=0.25）；再算四系纯伤 EHP 的算术/调和平均，比较 | 复算差 > 1e-6 → blocker；与算术平均差 ≤ 1% → blocker（红线 N6）；恰好等于调和平均 → blocker |
| **I4** | EFT 往返无损 | `save_eft → load_eft → calculate`，比对 8 项指标（EHP/DPS/alpha/align/cap稳定/耗尽/cpuFree/pgFree） | 任一差 > 1e-6 → high |
| **I5** | 抗性叠加 = 共振率相乘 | 裸船（`items=[]`）算出基础共振，`ship/bare` 必须等于模块共振率的乘积（逐层四项） | 不成立 → high |
| **I6** | 每个数值都带 provenance | 递归遍历六视角 overview 的**每个数值叶子**，必须能继承到 `measured/assumed/unknown`；有权威表时逐值对拍 | 缺 provenance → high（红线 N3）；与权威表不一致 → medium |
| **I7** | 解析失败必含可修复结构 | 4 个坏输入（乱文本 / 未知模块 / 未知船名 / 坏 JSON），校验 `line/raw/failed_at/candidates/reason` 齐全且取值合法 | 结构缺失或取值越界 → high |

### 3.1 I3 的两个易犯错误（重点盯）

1. **把混合 EHP 当四系算术平均**（红线 N6）——本 fit 实测：混合 8854.96 / 算术 9351.53（差 5.6%）；
2. **把混合 EHP 记成"调和平均"**（旧台账错记，§3 第 6 条已改为指向第 27 条）——调和 9218.97，
   与混合也不等；「等于调和平均」只在**单层**时成立。

### 3.2 I5 的属性 ID 陷阱（已实测）

- 船体结构层共振：EM **113** / EXP **111** / KIN **109** / THM **110**（不连号）；
- **模块侧**结构层共振走另一组：**974/975/976/977**（DC II 四项均为 0.60）；
- 护甲 267–270 / 护盾 271–274 两组模块与船体同 ID。

runner 对结构层用「任一映射成立即通过」的宽松判定（因 DC II 四值相等无法反解顺序），
但**不接受"相加"或"带堆叠惩罚"的叠加方式**。

### 3.3 模式（mode）维度：字段规格 §10.2 的承诺

顶层 modes 块（与 iews 平级）必须给出本船**全部可用模式**，每条含
mode_id / mode_name / ehp_mixed / dps_base / align_time_s。runner 三层校验：

1. **结构**：有模式的船必须有 modes；Hecate 三模式（Defense/Propulsion/Sharpshooter）齐全；
   无模式的船应为空（非空 → 口径错误）；
2. **方向**：Defense ehp_mixed ↑、Propulsion lign_time_s ↓、Sharpshooter dps_base ↑
   （方向比绝对值稳，能抓住模式接错）；
3. **数值**：用引擎独立重算逐项对拍；**最小探针配装**（Hecate + 1 炮）再与
   ixtures/f3-hecate-modes.expected.json 的标定值对拍。

> 权威样本口径（Lead 裁决）：模式数值的文档快照只认**最小探针配装**；
> 对 killmail 样本只验结构与方向，不把它的模式值当快照。

## 4. 五类缺陷的判定标准

> 分类计数口径。每条缺陷必须能写出：**位置（JSON path） / 期望 / 实际 / 复现命令**。

### 4.1 字段缺失（`字段缺失`）

| 判据 | 严重度 |
|---|---|
| 六个视角里缺任何一个（`firepower/survivability/mobility/resources/constraints/stability`） | blocker |
| 某视角缺 `overview` 节点 | blocker |
| 本计划 §2 的 41 个字段缺任何一个 | high（`weapons/dps/dph/range/ehp*/speed/align/cpu/pg/capacitor/hard_violations/tier_violations` 为 high，其余 medium/low） |
| 字段存在但规格要求的子键缺失（如 `dps.base` / `capacitor.recharge_s`） | medium |
| `weapons[]` 元素缺 `family/name/count/ammo_name` | medium |
| 本计划 `confidence=E` 的字段未给 `confidence` | medium |
| `confidence` 取值不在 A–E | medium |

### 4.2 口径错误（`口径错误`）

「值与口径不符」——**数值算出来了，但不是规格要的那个东西**。

| 判据 | 例（本 fit 实测基准） | 严重度 |
|---|---|---|
| 字段值 ≠ 来源属性（按语义直查表，容差 0.1%） | `ehp_mixed` 报 9351.53（四系算术平均）而应为 8854.96 | high |
| `ehp_mixed` 与四系算术平均差 ≤ 1% | 红线 N6 | blocker |
| `damage_split` 按**弹种数量**加权而非伤害量 | 四值之和虽为 100 但比例错 | medium |
| `range` 三档算错（如 `optimal+falloff` 与 `optimal+2falloff` 混用） | 应为 1350 / 2600 / 3850 | high |
| 字段自相矛盾：`firepower.hardpoints_free` ≠ `resources.hardpoints_free` | 同一事实两个值（必须同一函数计算） | medium |
| `cargo.used` 把**已装填弹药**算进货舱 | 只算 `slot_type=="cargo"` 的项 | medium |
| 资源余量给百分比而非绝对值 | 规格 §4「余量一律给绝对值」 | medium |
| `slots.used` 把 cargo 项算进槽位 | 本 fit 应为 6/4/4/3 | medium |
| `overload` 用了普通 state 的数值（或反之） | delta 恒 0 | medium |
| `repair` 里无对应模块的层输出 `null` 或 `unknown` | 应为 `0.0` + `measured`（Lead 裁决） | medium |
| EFT 空槽标记的接受范围与引擎真实行为不一致 | `[Empty Medium Slot]` 引擎拒绝、预扫描却放行 | medium |
| 违反措辞禁令：输出「配装非法」 | 只能说「当前档位下超载 X」 | medium |

### 4.3 单位错误（`单位错误`，红线 N5）

| 判据 | 例 |
|---|---|
| 该是秒的字段输出了**毫秒原值**（含舍入后） | `capacitor.recharge_s = 280000`（应 280.0）；`cycle_time_s = 2304.636`（应 2.304636） |
| 该是 ×1000 换算后的字段输出**原始值** | `application.tracking_rad_s = 444.366`（应 0.444366） |
| `warp_speed_au_s` 输出 `600`（属性原值）或 `13.5`（错乘 3） | 应 4.5 |
| 反向错误：把已是秒的 `-1 alignTime` 再 ÷1000 | `align_time_s = 0.0119`（应 11.861） |
| 字段名带单位后缀但量级违背常识 | `*_s` > 3600 / `*_rad_s` > 10 / `*_au_s` > 50 / `*_mps` > 1e6 |

判定实现：①用声明里的 `source_attr` 定向比较（该不该缩放在缩放表里查）；
②泛化扫描——任何数值若等于某毫秒/×1000 属性的**原值**（按 0–6 位小数任一种舍入匹配）
且不等于其物理值 → 单位错误；③后缀量级常识。

### 4.4 provenance 错误（`provenance 错误`，红线 N3/N4）

| 判据 | 严重度 |
|---|---|
| 数值叶子没有任何 provenance | high |
| provenance 取值不在 `measured/assumed/unknown` | high |
| 与投影层权威表 `provenance.tag(attr_id)` 不一致（权威表就绪时） | medium |
| 用默认值冒充 `unknown`（有默认值却标 unknown，或反过来） | medium |
| 「未建模」被塞进 provenance（如应用层标 `assumed` 当"未知"） | medium（该用 `confidence=E`） |

### 4.5 不变式失败（`不变式失败`）

见 §3 的判定列。I1/I2/I3 失败为 blocker，I4/I5/I6/I7 为 high（I7 的错误缺行号为 low）。

## 5. 严重度与裁决

| 严重度 | 含义 | 对结论的影响 |
|---|---|---|
| `blocker` | 视角/字段整块缺失，或不变式 I1–I3 失败 | 直接判**不通过** |
| `high` | 口径/单位/provenance 错误，会让 agent 得出错误结论 | 直接判**不通过** |
| `medium` | 子字段缺失、可信度标注缺失、自相矛盾 | 判**不通过**（需修） |
| `low` | 观察项（如错误结构里缺行号） | 记录，**不阻塞**通过 |

`status` 语义：`pass` / `fail` / `blocked`。
`blocked` = 取不到任何一套六视角结构（实现未就绪）——**不得误报为 pass**。

## 11. provenance 实例规则与载机口径（T-27 / T-28）

### 11.1 实例规则：值缺失 ⇒ `unknown`

- 某叶子在本次计算里**值为 `None`** → provenance **强制 `unknown`**，覆盖属性级静态表；
- 值存在时仍按 `evefit/project/provenance.py` 的 `tag(attr_id)` 比对；
- **数组元素口径**：一条路径只有一个标签。`weapons[].ammo_name` 混装（一门有弹、一门没有）
  → 按缺值判 `unknown`；全部有弹才算 `assumed`。**不按元素逐个要求**。
- 实现：`check_provenance_instances`（按路径聚合）+ `field_spec.json` 的 `provenance_rules`。

### 11.2 载机（fighter）口径

- **`dps.fighter` 只反映已发射的中队**（`fighter_tube` / flag 159–163）。
- 放在**机库**（`fighter_bay` / flag 158）的载机**不参与**伤害与槽位计算，只计入船级
  `-57`（机库占用 m³）→ 此时 `-58 = 0` 是**正确行为**，不是缺陷。
- 支援型中队（item 级 `-61 = 1`）进管后也不出伤害。
- 实现：`check_fighter_chain` 仅在「`-62 fighterTubesUsed > 0` 且非支援型且无
  `fighters_in_bay_only` flag」时才要求 `dps.fighter > 0`。

### 11.3 I3 的适用范围

- 核心不变式：`ehp_mixed == Σ_layer HP / Σ_i(w_i × r_i,layer)`（blocker）。
- 「与算术平均差 >1%」**只是样本能否区分口径的性质**，不是实现正确性；层抗性接近均匀时
  （如结构坦）两者天然接近 → 记 **low 覆盖度观察**，不得当红线。
